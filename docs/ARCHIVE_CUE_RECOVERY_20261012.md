### 1.1 缓存与取消的具体规则

- 缓存键包含外层文件的完整路径、卷序号、文件 ID、长度和修改时间，以及宽字符成员名、资源限制。文件替换或正常修改后重新解压。
- 只保留一个当前任务；旧任务若仍有活跃读取者，其数据继续有效。不存在无限增长的全专辑缓存。
- 普通释放最后一个读取者时，可让当前任务继续完成，供随后同源 CUE 子曲目或元数据读取复用。
- 若读取者已取消／超时，且它是最后一个使用者，则取消生产任务。一个读取者取消不会中断另一个使用者。
- 回调仅由调用者线程轮询；生产线程不持有播放器或元数据任务的回调。宿主包装流保留回调状态，Clone 也保持其有效期。
- 分卷 RAR 根据 `RAROpenArchiveDataEx.Flags & ROADF_VOLUME` 禁用跨次保留缓存，**包括目标成员本身未跨卷的情况**；仅靠第一卷的文件身份不足以验证整个卷组。
- Read 到成员末尾必须等待最终校验结果，不能因为已产生声明长度就提前返回成功。播放器 EOF 再确认容器尾部，防止解码器提前停止掩盖归档错误。
- 程序退出先释放相关读取者，再 `clear_cache`，最后卸载 DLL。大成员临时文件在任务销毁时删除。

限制继续保留：默认成员上限 8 GiB、RAR 字典默认 256 MiB／硬上限 512 MiB、小成员内存默认 16 MiB／硬上限 64 MiB。CUE 文本读取在解压前限制为 16 MiB。等待默认 30 秒，可取消；大成员的磁盘空间不足会返回错误。

### 1.2 DLL 与宿主分工

**原版 5.7.9 的 RAR 引擎位于 `TTPlayer.exe`，不是原版 `ttpcomm.dll`。**

| 原版地址 | 职责 |
| --- | --- |
| `004738B5` | 根据扩展名创建 ZIP 或 RAR 对象 |
| `00473287` | RAR 对象构造 |
| `00473338` | 枚举 RAR 成员 |
| `00473580`、`00473702` | 同步／后台成员解压 |
| `0047366F` | 取消 RAR 工作 |
| `00474051` | 通用成员导入及 CUE 展开 |

重建版将 UnRAR 7.3.1、音乐 ZIP 及成员存储集中到 `ttpcomm.dll`。单独替换原版播放器的 `ttpcomm.dll`，不会把原版 EXE 内的旧 RAR 调用自动改成新版，也不会自动增加 RAR5。

## 2. 原版二进制对照结果

基准 EXE SHA256：`c7999ea5823469c1684148cac1bd196009824348ccac5cdd45978f8fb574e28c`。

在独立原版测试进程内核对 PE 基址、架构与 vtable 后，调用实际的 `004738B5` 和归档对象虚表 `+0x14`，比较输出字节散列；路径分类直接调用 `004E31EE`。没有替换或修改用户正在使用的原版进程。

| 样本 | 原版 Win11／XP／Win7，三者一致 | 修复后 |
| --- | --- | --- |
| Deflate ZIP，WAV 与 CUE | 成功且字节正确 | 一致 |
| Stored ZIP，WAV 与 CUE | 打开归档成功，音乐成员读取失败 | 保留已有 Stored 支持，属于改进 |
| 有 ZIP 注释的样本 | 归档打开失败 | 支持 EOCD 注释，属于改进 |
| OEM 936 的 `81 41` 与 `81 61` 两个名称 | 分别返回正确的两个成员 | 已修正混淆，结果一致 |
| 错误 CRC，压缩内容正常 | 原版接受，字节仍正确 | 拒绝并报告校验失败，属于加固 |
| 删除 Deflate 最后一个压缩字节，后面仍有中央目录 | 原版接受本样本，字节散列正确 | 严格限制压缩成员范围，拒绝截断 |
| RAR4 Stored 成员 | 成功且字节正确 | 一致 |
| RAR5 成员 | 原版打开失败 | 保留 UnRAR RAR5 扩展 |

关于截断样本：`0041F185` 的返回确实要求 `Z_STREAM_END`，但 `0041F257` 每次读取 16 KiB，没有按该成员声明的压缩长度裁剪输入，因此可能把后续 ZIP 结构字节送入 inflate。**要求结束标记不等于可靠拒绝所有成员截断。** 本轮实测纠正了仅凭结束条件推断全部损坏行为的不足；重建版不复制这种越过成员边界读取的容错。

`004E31EE` 的 7 个实测输入：普通相对路径、单反斜杠、双反斜杠 UNC、相对 `other.zip|member`、盘符绝对路径、`..`、HTTP URL。三系统分类一致；重建版的 CUE 路径测试按这些结果断言。双反斜杠／盘符／协议形式视为绝对；单反斜杠及相对显式归档仍参与字面拼接。

## 4. 构建、打包与部署顺序

- 新入口 `ttpcomm_query_archive_stream`，导出序号 **503**，返回 ABI 2；502 保持 ABI 1 并可查询 ABI 2。新增接口包含 enumerate、open_member、status、clear_cache。
- SDK 已同步到 `rebuild/third_party/ttpcomm-sdk`。重建版启动验证新接口，Actions 的组件下载与打包同时要求 503 及 ABI 2 元数据。
- 发布时应**先发布新 ttpcomm，再构建播放器**。尚未发布新 DLL 时，Actions 应明确拒绝不满足接口要求的旧组件，避免产生运行时不匹配的包。
- 本地包位于 `rebuild/build/Release/TTPlayerRebuild-2026.10.12.zip`；独立组件包位于同目录 `ttpcomm-2026.10.12.zip`。组件元数据注明 `local-unpublished-build`，没有将本地构建伪称为 GitHub 已发布版本。
- 发行包只放规定的运行文件和 SHA256 清单；不包含测试。替换时关闭播放器，将包内 EXE 与 DLL 一起更新。

## 5. 仍保留的差异和下一步

1. **导入与信息读取已追加修复和对照。** 恢复批次内去重、普通成员的文件名回退、CUE 初始未读状态，补齐包内 MP3／WAV 标签和封面、AIFF／AU 信息读取及错误传播。三系统原版导入和 Reader 对照、重建版每系统 250 项检查见 [第二轮记录](ARCHIVE_CUE_IMPORT_METADATA_PARITY_20261012.md)。仍不代表每个可视 UI 入口及调度时机都已逐帧一致。
2. **MIDI／CDA 已恢复按注册类型列出。** 进一步实测确认原版确实导入包内 `.mid/.midi/.rmi/.cda`，本轮已去掉硬排除；同时优先排除已注册的播放列表类型。原版 MIDI 流 Open／Read 返回 E_NOTIMPL，实际播放交给 `RenderFile` 的文件路径；CDA 依赖光驱。列出这些成员不等于支持从归档播放它们，流适配仍属于另行扩展。
3. **密码录入是扩展边界。** 已核对原版 RAR 回调 `004DFF63`，仅处理进度／取消，没有填充密码；未发现原版播放器的密码输入交互。RAR 服务可接收密码，播放器仍报告原因；本轮未新增密码窗口或 ZIP 加密。
4. **缓存仍仅覆盖当前成员。** 固实 RAR 切换到不同音频成员仍可能重新处理前置成员，不是无限缓存整个固实块。分卷组保留缓存需要以后为所有卷建立可靠身份。
5. **现代 ZIP 扩展独立规划。** UTF-8 标志、ZIP64、AES、额外压缩方法未在本轮实现；OEM 语义按原版保留。Stored、注释及更严格校验是有意保留的改进。
6. **只读不变。** 未新增包内标签、封面或 CUE 写回、任意嵌套归档。7z／TAR／GZ 方案及实施顺序见 [扩展分析](ARCHIVE_7Z_TAR_GZ_PLAN.md)。
