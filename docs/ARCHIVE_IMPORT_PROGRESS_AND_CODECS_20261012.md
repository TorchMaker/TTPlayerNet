# 压缩包导入、密码等待及额外解码修复

日期：2026-10-12。承接 [只读扩展第 6 节](ARCHIVE_EXTENSIONS_AND_READONLY_20261012.md#6-仍有差异与后续顺序) 与 [密码／文件头第 7 节](ARCHIVE_PASSWORD_AND_SIGNATURE_20261012.md#7-尚未覆盖的差异与建议顺序)。

本轮完成可取消的后台导入、并发密码交互合并、延迟计算密码指纹、TAR／gzip 的有界 CUE 缓存、7z BZip2／Zstandard、旧 ZIP 密码和旧 TAR 文件名兼容，以及 CUE 内嵌封面继承。**压缩包内容仍只读，不增加写回。** 剩余边界列于第 7 节。

## 1. 原版依据与保留行为

再次核对 5.7.9 `TTPlayer.exe.pseudo.c` 中 `00474051`：先调用 `004738B5` 取得归档对象，按其枚举顺序生成 `外层路径|成员名`；CUE 通过成员 Reader 读入，再由 `00473EC5` 展开；其余成员经播放列表／音频类型分类。临时结果按已有路径与分轨身份去重。并没有按文件名字母重新排序，也不会因为出现 CUE 就自动隐藏其引用的整轨音频。

本轮把枚举与读取移到工作线程，提交列表仍在界面线程；保留上述成员顺序、CUE 标签、分轨编号、整轨音频及同批去重规则。批次共享一个身份索引，避免每加入一个压缩包都重建此前所有曲目的索引。

原版 `004738B5` 只选择 ZIP／RAR。原版归档 IStream 的 Write／SetSize／Commit 分别为 `0040F7F0`／`0040BE91`／`00407310`，实际返回 `E_NOTIMPL`。后台导入进度、新格式、密码记忆及本轮缓存是重建版扩展，不能描述为原版已有界面的逐像素恢复。只替换原版播放器的 `ttpcomm.dll` 也不会改变其 EXE 内的归档工厂。

## 2. 大文件导入体验

### 2.1 工作线程与事务提交

- 目录、多文件、播放列表、CUE 和压缩包批次在工作线程扫描；普通单文件／URL 的快速路径保留。
- “导入歌曲”窗口显示当前文件、阶段和已找到曲目数，提供取消。已知长度显示当前扫描阶段进度，未知长度显示活动状态，不推算虚假的整体完成时间。
- 界面保持消息分发，播放计时和密码请求继续处理。工作线程只持有设置快照及临时曲目，不操作 PlayerWindow 或列表控件。
- 取消时停止枚举、CUE 读取和后续遍历，等待工作线程结束后丢弃本批新增结果；“替换列表”也不会先清空原列表。
- 同一批多路径只显示一个进度窗口。失败摘要最多展开 8 项，避免坏目录连续弹出数百个错误框。
- 导入期间稳定目标列表；外部“打开文件”命令排队，关闭请求先取消导入再继续关闭。密码框以导入窗口为模态父窗口。

“取消”是分块检查与引擎回调取消；已经进入的系统文件调用仍须返回，不承诺所有故障磁盘或网络共享上的取消都是瞬时的。

### 2.2 TAR／gzip CUE 缓存

此前 tar.gz 枚举需走到容器末尾验证 CRC，随后读取每份 CUE 又重复展开同一专辑。现在首次完整枚举顺便收集小型 CUE，**只有整个扫描及 gzip 校验成功后才发布缓存**。

- 缓存最多 128 份 CUE、合计 16 MiB，并服从调用方更小的内存预算；不缓存整张音频镜像。
- 以外层绝对路径、卷／文件身份、大小、修改时间验证缓存；读取期间持有禁止写入的外层句柄。
- 命中后仍检查成员大小、成员数量及 gzip 展开预算。`clear_cache` 同时清除此缓存；损坏尾部、取消扫描不能发布未验证内容。
- 缓存与正在建立的新缓存可能短暂同时存在，最多两份有界文本集合。它不等于无限制的多歌曲缓存，也不改变音频成员的磁盘后备策略。

固实 7z／RAR 解压前序成员、gzip 校验尾部时，流等待现在记录引擎推进；即使目标成员暂时没有新增输出，只要解压仍有进展就不按固定等待时间误报超时。无进展时仍有超时和取消。

## 3. 密码等待优化

同一外层路径、同一重试阶段的并发请求共享密码框；一个读取者取消不撤销其它读取者。最后一个等待者取消时才放弃该请求；已放弃的排队项会继续唤醒后面的请求。

首次输入时先验证密码，不再无条件扫描大文件计算哈希。同名候选可先实际验证；只有需要匹配已改名的记忆记录，或用户勾选“记住密码”并验证成功，才计算完整 MD5＋SHA-256。指纹分块计算可以取消，取消不写入不完整记录。信息助手的读取超时从准备完密码数据包后开始，避免计算指纹消耗解码期限。

记忆规则保持为“文件名匹配，或者 MD5 与 SHA-256 同时匹配”，命中只允许尝试密码，不绕过实际解压／认证。仍使用当前 Windows 用户的 DPAPI，不保存明文密码。

## 4. 格式与封面补齐

| 项目 | 本轮行为及边界 |
| --- | --- |
| 7z BZip2 | 注册方法 `0x040202`；流式解码，支持固实块中的首个和后续成员，检查声明块大小及实际分配预算 |
| 7z Zstandard | 注册 7-Zip-Zstandard 方法 `0x04F71101`；支持当前 flags 及历史 3／5 字节属性、帧校验、截断检测、固实成员及声明窗口限制；没有外部字典文件支持 |
| ZIP 密码 | 先 UTF-8，再尝试本机 ANSI／OEM 代码页；不能无损编码的候选不尝试。传统加密及 AES 共用该规则，不猜测任意国家代码页 |
| ZipCrypto 校验碰撞 | 8 位密码头通过但完整 CRC 失败时，丢弃该候选所有临时输出，再尝试下一编码；未经认证的内容不交给音频 Reader |
| 旧 TAR 名称 | 非 PAX 的旧头路径先保留有效 UTF-8，否则按系统 ANSI 严格转换；PAX UTF-8 规则不改，UTF-8 系统区域不猜其它编码 |
| CUE 封面 | 文件属性和播放元数据继承引用音频的内嵌封面；标题、艺术家、专辑、分轨等仍使用 CUE 元数据；封面继承只读，不把保存动作转交给底层音频 |

新增解码器静态链接，构建时下载并核验固定源码：

| 库 | 固定版本 | SHA256 |
| --- | --- | --- |
| [bzip2](https://www.sourceware.org/bzip2/downloads.html) | 1.0.8 | `ab5a03176ee106d3f0fa90e381da478ddae405918153cca248e682cd0c4a2269` |
| [Zstandard](https://github.com/facebook/zstd/releases/tag/v1.5.7) | 1.5.7 | `eb33e51f49a15e023950cd7825ca74a4a2b43db8354825ac24fc1b7ee09e6fa3` |

配置在 `ttpcomm/cmake/archive_extra_codecs.cmake`。版权文本保存在 `ttpcomm/licenses/BZIP2-LICENSE.txt`、`ZSTD-LICENSE.txt`，不嵌入 DLL；运行包不包含依赖源码或命令行解压程序。继续使用 IA32、VC-LTL／YY-Thunks，不增加需用户安装的运行库。

## 7. 剩余边界与建议顺序

后续已实施的包内歌词、外置图片、ZIP／7z 分卷和三系统对照见 [ARCHIVE_AUXILIARY_AND_MULTIVOLUME_20261012.md](ARCHIVE_AUXILIARY_AND_MULTIVOLUME_20261012.md)。以下保留为本轮开始时的建议；当前剩余边界以新文档第 7 节为准。

1. **辅助文件关联**：本轮恢复 CUE 继承内嵌封面；包内外置 LRC／图片的完整搜索、编辑只读提示和关联缓存尚未实现。MIDI／CDA 保持原版特殊 Reader 的边界，不增加自动落盘或把包内 CDA 当成可读光盘。
2. **分卷及少见方法**：分卷 ZIP／7z、PKWARE 强加密／隐藏中央目录、TAR 稀疏音频映射和其它未注册 7z 方法仍不支持；RAR 仍可自动寻找同目录后续卷，缺卷明确失败。旧 ZIP／TAR 本地编码兼容不是任意代码页检测。
3. **固实音频复用**：已完成 TAR／gzip 小 CUE 的有界缓存；不同音频成员的固实块预取、多成员共享磁盘缓存和分卷整体身份仍可继续优化。不能用无界内存换取导入速度。
4. **更多错误界面对照**：当前已验证后端错误、取消、原版流和真实宿主流程；尚未逐项比对所有坏包提示的文本和时机。

压缩包成员写回按用户要求排除，不作为后续建议。
