## 1. 结论与实际修复

| 差异 | 根因 | 修复后 |
| --- | --- | --- |
| 同批次重复导入压缩包／CUE 产生重复条目 | 每次枚举直接追加，未模拟原版临时批次去重 | 以原始逻辑路径和子曲目序号去重；已有目标列表不参与本次去重，单独两次追加仍可重复 |
| 无标签成员被当作有 Title 标签 | 把文件名直接存入 `Track.title` | 保持标签为空，由显示格式执行文件名回退，自定义 `%T`／`%F` 可正确区分 |
| 磁盘 CUE 首曲有时长却没有完整格式信息 | 导入时根据 INDEX 预填时长，后续队列把它当成已经读取 | 与包内 CUE 一样初始化为 `-2`；Reader 再取得首曲、末曲的真实时长和音频格式 |
| 包内 MIDI／CDA 不出现在列表 | 宿主硬编码排除，不符合原版注册类型过滤 | 按注册类型列出；仍受 MIDI／CDA Reader 本身能力限制 |
| 宽泛插件把包内播放列表当成歌曲 | 未在音频类型匹配前排除播放列表 | 先检查播放列表类型，再匹配内置音频／插件，即使插件声明 `*.*` 也不加入 M3U |
| 包内 WAV／MP3 能播放却读不到信息，关联 CUE 也失败 | 文件信息助手拒绝归档路径，内置标签读取只接受磁盘文件名 | MP3／WAV 的磁盘与 IStream 复用同一套解析；AIFF／AU 等回退到已有流式音频源 |
| 包内 MP3 播放时缺少标题、封面 | 播放器显式跳过归档的内置标签补充 | 播放时也读取 ID3／APEv2、封面及已有增益字段；独立流游标不改变解码器位置 |
| 后缀错误的包内音频丢标签 | 将扩展名当成内置读取器的最终结论 | 按内容验证 MPEG／WAVE，再选择成功的读取器 |
| 只读头部就报告信息读取成功 | 元数据读取没有等待完整成员的最终校验 | 返回成功前确认解压和 CRC；保留具体归档错误，CUE 不用后续候选文件的失败覆盖 CRC／密码错误 |

生产改动位于 `src/ui/player_window_file_intake.cpp`、`src/app/file_info_worker.cpp`、`src/audio/builtin_file_info.cpp`、`src/audio/audio_engine.cpp` 和对应内置读取头文件。没有增加另一套 MP3 标签解析器，也没有将音频成员整体复制进内存后再读标签。

归档信息一律清除写入能力：包内 MP3、插件格式及 CUE 的文件属性不会因为底层 Reader 支持写标签而误启用保存。信息助手在释放 Reader 后清理归档缓存，再释放 DLL 引用。

## 2. 原版伪代码与二进制证据

原版 `TTPlayer.exe` SHA256：`c7999ea5823469c1684148cac1bd196009824348ccac5cdd45978f8fb574e28c`。探针只在独立测试进程内调用经过校验的 x86 地址，不修改正在使用的原版播放器。

| 地址 | 已核对的行为 |
| --- | --- |
| `00474051` | ZIP／RAR 枚举、CUE 展开及按注册类型导入；保留成员顺序，不因存在 CUE 而删除整文件条目 |
| `00473EC5` | CUE 导入及临时批次去重；保留 TITLE、PERFORMER、ALBUM、序号 |
| `0041EA0C`、`004AD1A4` | 路径＋子曲目对象及未读取时长 `-2`；文件名回退字段不能当成 Title 标签 |
| `0041B572` | 用原始 UTF-16 单元计算身份散列；实测大小写不同的路径可形成不同条目 |
| `004742DD` | 单独显式加入成员允许重复，不等同于批次枚举去重 |
| `00480386`、`004801E7`、`00481759` | 添加时读取、批量读取和可视行延迟读取路径 |
| `004AE7FD` | 使用标签格式／默认文件名格式生成显示文字，结合缓存和文件时间决定是否查询 |
| `004ADA76` | 实际 Reader 查询，取得 CUE 子曲目时长、源格式及标签 |

原版自动对照使用 10 条成员的 ZIP／RAR4 样本，包括两条 CUE 子曲目、其 WAV 源、MID／MIDI／RMI／CDA、仅大小写不同的成员；另外包含应排除的 M3U、未知类型及嵌套压缩包。

三系统原版结果一致：

- 初次 ZIP 导入 10 条；同临时批次再次导入仍为 10 条。
- 改变外层路径大小写后，同批次为 20 条；再显式加入 WAV 成员为 21 条。
- 新临时批次再次导入为 10 条，不依赖此前的对象是否已经存在。
- 磁盘 CUE 初次和同批次重复导入都为 2 条；RAR4 初次和重复都为 10 条。
- `TRACK 01` 和 `TRACK 07` 在列表内使用子曲目 ordinal 1、2。
- CUE 初始显示为 `First Artist - First Title`、`Disc Artist - Second Title`；普通无标签 WAV 使用文件名 `image`。
- CUE 和整文件导入时均为 `-2`。直接调用 `004ADA76` 后分别为 **1000、2000、3000 毫秒**，格式为 `PCM|PCM Audio`，CUE 标题保持不变。

注意：原版对象的 `+0x08` 是编码说明，Reader 查询后为 `PCM|PCM Audio`，不是 Title；真正标签存储在其键值表。早期仅凭字段位置作出的“文件名写入 Title”解释已纠正。

仅调用原版标题格式化函数并不总会触发 Reader；探针同时记录查询前及显式查询后状态，避免把缓存命中误当成已经完成信息读取。

## 4. 原版限制与尚未新增的扩展

1. **归档 MIDI／CDA：** 已恢复列表行为；MIDI 的原版 IStream Open／Read 返回 E_NOTIMPL，实际通过路径建立 DirectShow 图，CDA 则依赖光驱。未新增归档临时落盘的 MIDI 播放适配，也不把 CDA 描述文件当成音频数据。
2. **密码交互：** 原版 RAR `00473338`／`00473580` 使用的打开参数没有提供密码；其回调 `004DFF63` 只处理消息 1 的进度和取消，其他消息返回 0，没有填写密码。现有 RAR 服务可接收密码，但播放器的密码输入窗口、ZIP 加密仍属扩展工作，不作为本轮遗漏的原版 UI 恢复。
3. **缓存：** 当前成员可供相邻 CUE 子曲目复用；切换固实 RAR 的不同成员仍可能重解压前置数据。原版 `00473702` 从头遍历目标成员，完成后关闭解压对象，也不能据此推断原版具有整个固实块的无限缓存。分卷整体身份、多成员缓存和相关性能优化仍单独规划。
4. **写回及新增格式：** 不新增包内标签／封面／CUE 写回、任意嵌套归档、ZIP64／AES／额外 ZIP 压缩方法、7z／TAR／GZ；见 [格式扩展方案](ARCHIVE_7Z_TAR_GZ_PLAN.md)。
5. **对照范围：** 字面路径身份覆盖已测试的大小写差异；没有穷举原版散列表碰撞、所有地区字符比较规则、所有插件及损坏文件组合，不宣称二进制级完全等价。
