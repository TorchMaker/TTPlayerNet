# 压缩包内歌词、图片与分卷读取（2026-10-12）

本轮承接 `ARCHIVE_IMPORT_PROGRESS_AND_CODECS_20261012.md` 第 7 节，按关联文件、分卷、缓存身份、原版及旧系统验证的顺序实施。**所有压缩包及成员保持只读**；没有标签、图片、歌词、CUE 或增益写回。

## 1. 原版依据与实测范围

本机、XP、Win7 中的隔离原版实例均得到相同结果：

- Deflate ZIP 中的 LRC 与 PNG 可由原版归档接口完整读出，校验摘要一致；同一个逻辑路径传给文件属性查询则返回不存在。这说明“归档能读文件”不等于“原版歌词目录搜索已经支持包内文件”。
- 本轮 Stored ZIP 在原版的该成员读取接口失败，Deflate 对照成功；保留此原版差异，不回退重建版已支持的 Stored 读取。
- 标准分卷 ZIP、ZIP64 分卷、数字分卷 ZIP／7z 的本轮样本在原版均未能读出目标成员；普通 7z 也未获原版归档工厂支持。
- 本次是在重建宿主中扩展关联文件和分卷读取。仅替换原版播放器的 `ttpcomm.dll` 不会改写原 EXE 的归档工厂或本地歌词搜索。

上述是伪代码与指定样本的行为对照，没有宣称所有错误窗口的像素、文案和出现时机完全一致。

## 2. 包内外置歌词

`<Sound Folder>` 对包内曲目解析为对应成员目录；根目录曲目使用明确的包内根目录，避免把 `|` 前面的压缩包名称算进歌曲文件名。

搜索继续使用原有优先次序和匹配分数：显式关联、歌手与标题、歌曲文件名；同一基名先 `.lrc` 后 `.txt`。递归与部分匹配仍由既有选项控制，最多四层。其它配置的磁盘搜索目录继续可用。

读取走只读归档流，最多 16 MiB，等待长度和完整性验证后，将字节交给 `DecodeLrcBytes`。因此 UTF-8／UTF-16／旧中文编码、普通与逐字歌词共用同一解析逻辑。异步搜索保留 DLL 引用，取消时不向已经结束的搜索交付结果。

编辑器可以读取包内原始文本。普通“保存”会说明包内歌词只读，要求使用“另存为”；建议保存位置是压缩包所在磁盘目录，文件名取歌曲成员名。底层文本写入也拒绝含 `|` 的逻辑路径。

## 3. 关联表与图片

原 `.rll` 使用 `|` 分隔字段，旧实现因此拒绝包含 `|` 的媒体或歌词路径。现保持普通记录格式不变，只对归档记录使用 `@TTPlayerLyricAssociation/2|` 前缀和明确转义：`%25` 表示 `%`，`%7C` 表示 `|`。仅对带前缀的记录解码，普通文件名中的百分号不改变；无歌词标记和 CUE 子轨号继续独立保存。

压缩包外层被既有后缀修正功能重命名后，媒体关联键、同包歌词关联值和当前歌词路径一起更新；普通磁盘歌词保留原位置。

封面优先使用音频内嵌图片。没有内嵌封面时，在**同一成员目录**查找：

1. 歌曲同名图片。
2. `cover`。
3. `folder`。
4. `front`。

每组尝试 PNG、JPG、JPEG、BMP、GIF，并检查图片签名；单张上限 16 MiB。图片解码和显示继续使用播放器既有 WIC／GDI+ 路径，XP 的 PNG 解码有实际验证。不会跨到另一个专辑目录寻找封面。文件属性窗口、播放元数据与 CUE 继承均已接通，外置封面没有写入能力。

## 4. 分卷 ZIP／7z

| 命名及结构 | 实现 |
| --- | --- |
| `album.z01`、`.z02`…最后 `album.zip` | 从最后一卷 EOCD／ZIP64 Locator 得到卷数；中央目录起始卷、成员起始卷与卷内偏移分别转换为全局位置 |
| `album.zip.001`、`.002`… | 连续字节分卷，ZIP 中的偏移按拼接后的全局流解释 |
| `album.7z.001`、`.002`… | 连续字节分卷；同一可定位输入交给现有 7z 引擎，保留固实、密码、字典及内存限制 |

可选择组内任意一卷导入。逻辑路径统一到标准 ZIP 的最后 `.zip` 或数字分卷的 `.001`，多选同组成员不会重复添加歌曲。已识别的分卷后缀视为有效后缀，不会误提示把 `.001` 单独改成 `.7z` 而破坏组名。

读取只打开同目录、连续命名的卷，最多 4096 卷，不合并整包，不使用成员名创建临时磁盘文件。跨卷读取、定位、Clone 沿用现有成员流；中间缺卷、标准 ZIP 缺少最后一卷、数字分卷缺少尾部均有检查。ZIP 保留 CRC／AES 认证；7z 保留头部及数据完整性校验。

实现依据：[PKWARE APPNOTE](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT) 的磁盘号和 ZIP64 偏移定义，以及 [7-Zip SplitHandler](https://github.com/ip7z/7zip/blob/main/CPP/7zip/Archive/SplitHandler.cpp) 的数字分卷模型。没有把标准分卷 ZIP 简化为仅拼接字节后按单卷偏移解析。

## 5. 缓存、密码与大包

- ZIP／7z 的缓存身份包含组内**每一卷**的完整路径、文件身份、大小和修改时间。读取期间持有只读、拒绝并发写入的文件句柄；完成后释放。只改后续卷也不能命中旧成员缓存。
- 记住分卷密码时，MD5 和 SHA-256 按卷顺序读取整组内容，指纹缓存也核对整组身份。仍然是文件名匹配或两个摘要同时匹配后选择候选密码，随后真实解码验证；没有跳过密码校验。
- TAR／gzip 的完整枚举成功后，增加有界目录索引缓存，并将原小 CUE 缓存扩展到 LRC／TXT 和图片。最多 128 份辅助成员、16 MiB 数据；目录元数据另限 16 MiB，两者均服从调用方更小预算。失败、取消、文件身份变化和 `clear_cache` 均不会留下可复用的错误结果。
- 命中目录缓存仍检查取消、成员数量和已验证的展开预算。音频的一个当前成员任务与小辅助文件缓存分开，读取歌词、图片不会挤掉相邻 CUE 共用的音频任务。
- 既有大包工作线程、阶段进度、取消回滚与并发密码窗口合并继续通过回归。

## 7. 仍保留的边界及后续顺序

本节后续修正见 [分卷定位、RAR 整组身份与缓存修正](ARCHIVE_VOLUME_RESOLUTION_AND_CACHE_20261012.md)：新增跨目录缺卷窗口、RAR 实际卷组及指纹、三个有界保留槽，并修正 Win7 同大小、同修改时间覆盖后的缓存失效。下列内容保留为本轮结束时的历史边界；最新剩余项以新文档第 7 节为准。

1. 本轮新增标准同目录分卷。跨目录／需人工选择换卷、非约定组名、换盘式多介质归档仍不支持；缺卷时明确失败。
2. RAR 继续由 UnRAR 自动寻找卷，跨次成员缓存仍对 RAR 分卷禁用。RAR 密码指纹仍是传入外层文件的指纹；若要统一整组密码指纹，应通过 UnRAR 的卷回调收集实际卷身份，不能猜测不同代际命名。
3. 不同音频成员的 7z／RAR 固实块共享与后台预取仍未实现。优先补组身份和有界淘汰后再扩展，不能用无界内存换速度。
4. PKWARE 强加密／隐藏中央目录、TAR 稀疏音频映射和未注册的 7z 方法仍明确不支持。已有密码支持不等于支持所有加密变体。
5. 更多原版坏包窗口的文案与时序、非同目录图片布局可另做定向对照。MIDI／CDA 仍保留其特殊 Reader 和光盘语义。

归档写回按用户要求排除，不列入后续计划。
