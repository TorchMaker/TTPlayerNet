## 2. 缺卷窗口及位置传递

缺少标准 ZIP、数字 ZIP／7z、RAR 卷时，显示“选择压缩包分卷”：归档名、所需卷路径、可编辑的实际路径、浏览、继续、取消。浏览复用现有现代打开窗口与 XP 回退。

- 可以选择其它目录中的卷，也可以手动选择不同文件名的实际卷。
- 选择一次目录后，同组后续约定名称会先在该目录寻找，避免每卷都弹窗。
- 正常位置中已存在的卷优先；被移走、损坏或取消的请求不会被当作成功。
- 文件存在不代表卷正确：仍需通过 ZIP 偏移及 CRC／AES、7z 完整性、RAR 头与数据校验。重复选择同一个物理文件作为不同卷会被拒绝。
- 导入失败／取消不提交部分歌曲列表；错误后的路径映射会清理，后续导入可以重新选择。
- 多线程请求在 UI 线程统一显示，沿用密码窗口的排队和相同请求合并。选择回调不留在后台解码任务中。
- 位置保存在当前运行会话；歌曲信息子进程通过受 DPAPI 保护的会话包收到位置。没有把明文密码放入命令行或包内文件，也没有移动、合并或改写原卷。

工作进程包允许只包含分卷位置、不包含密码。包大小继续受限；约定名称通常只需传递一个目录来源。大量完全任意命名的卷可能超过会话包预算，见第 7 节。

## 3. RAR 实际卷组

使用 UnRAR 的 `UCM_CHANGEVOLUMEW`：

1. `RAR_VOL_ASK` 请求定位缺少的卷。
2. `RAR_VOL_NOTIFY` 记录引擎实际打开的文件。
3. 在完整扫描卷链之后才提供卷清单，并用只读、拒绝并发写入的句柄保留组身份。

没有自行猜测 RAR4／RAR5 的后缀代际。从非首卷开始时，先由 RAR 头的 `ROADF_NEWNUMBERING`／`ROADF_FIRSTVOLUME` 判断，再复用 UnRAR 的 `VolNameToFirstName` 定位首卷；定位后重新检查首卷标志。导入路径归一到首卷，选择同组多个卷不会重复导入。必要的密码／卷位置会话随逻辑路径归一而传递。

组身份包含每一卷的完整实际路径、磁盘号、文件 ID、长度、最后写入时间及变更时间。最大 4096 卷，仍采用分段只读输入，不生成整包拼接副本。

RAR 记住密码时，MD5 和 SHA-256 按实际卷序覆盖整组内容。文件名或两个摘要同时匹配只用于选择候选，仍须通过请求的真实归档操作校验；读取加密成员继续等待完整 CRC／认证。RAR 加密头会隐藏卷链；对改名的已保存记录，可以先用保存的候选解开头部取得完整卷清单，但只有整组摘要匹配且请求的操作成功才接受。

## 4. Win7 缓存失效与 XP 初始化修正

Win7 初次执行“只覆盖最后一卷”测试时，替换保留了目标的文件 ID、大小及最后写入时间，旧的身份键没有变化，因而命中了旧成员。这是生产缓存的遗漏，不是通过延迟测试来规避的问题。

现在额外读取 `FileBasicInformation.ChangeTime`，并同时修正：

- ZIP／RAR／7z 的成员任务身份。
- 整组密码摘要的短期缓存身份。
- TAR／gzip 的目录与 CUE／LRC／图片辅助缓存身份。

`ChangeTime` 与 `LastWriteTime` 的语义不同，不能只比较后者。[Microsoft 文件基本信息说明](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_basic_info)。代码动态解析 `NtQueryInformationFile`，使用 `FileBasicInformation`，未引入 Vista 专用静态导入。[Microsoft 原生查询接口说明](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntqueryinformationfile)。

查询失败或返回无效变更时间时，保留正常读取，并禁用相关跨次缓存命中。回归主动恢复替换前的最后写入时间，分别验证后续 RAR 卷和 TAR 歌词能读到新内容。

XP 回归又发现：动态加载的 DLL 内，新增函数局部静态变量未正确得到函数地址，缓存因此始终禁用。诊断中静态指针为零，同一位置直接调用 `GetProcAddress` 则返回有效地址，排除了 XP 缺少该接口和结构大小错误。最终改为直接解析接口，避开这处局部静态初始化；XP 的整组缓存复用与同时间覆盖失效均有专门用例。诊断输出已移除。

每次打开查询系统文件身份和时间，不逐次计算整包摘要；记住密码时的指纹另用完整内容 MD5 和 SHA-256。

## 5. 有界成员复用

以前只保留一个当前音频成员，切到另一首后再返回会重新解码。本轮调整为最多三个保留槽，按最近使用顺序淘汰：

- 当前成员保留原有上限，默认最大 8 GiB；大 CUE 音频仍可被相邻子轨复用，不因为新增 128 MiB 历史门槛而丢失原能力。
- 最多另外保留两个**已完整校验、各不超过 128 MiB** 的历史成员。
- 新成员打开时，旧的未完成任务在没有读者后取消；不积累后台解码线程。
- 当前流和 Clone 使用独立位置；淘汰与 `clear_cache` 不破坏仍被调用者持有的流。
- 成员上限、字典上限、内存预算、密码及全部卷身份仍参与命中判断。

默认每个小成员内存门槛 16 MiB，最多三个保留槽共 48 MiB；调用方提高门槛后硬上限共 192 MiB。超过门槛使用自动删除的临时文件。额外历史磁盘数据不超过 256 MiB，当前成员继续受调用方上限约束。这些是保留缓存的预算，不包含解码器字典或调用者主动保持的其它流。

这里实现的是已完成成员复用。首次读取另一个固实成员仍可能重解前置块；尚未实现共享解码器字典或自动预取下一曲。

## 7. 后续边界与顺序

1. **固实块共享与预取。** 本轮先补齐完整身份与有界淘汰。后续需要独立处理固实块内多个成员的解码状态、校验完成时点、取消和后台预算，再接入播放模式决定的下一曲；当前不提前解码整个固实归档。
2. **会话位置长期保存。** 当前选择在本次运行有效，标准同目录卷不需要映射。大量任意命名卷受元数据工作进程 240 KiB 原始会话包预算限制；不保证超出预算的映射全量传给子进程。
3. **换盘式多介质。** 目前要求实际卷同时可访问，以便持有整组只读身份；逐张换盘、卸载原卷再装下一卷仍未支持。自解压 EXE 也不列为本轮归档输入类型。
4. **特殊格式。** PKWARE 强加密／隐藏中央目录、TAR 稀疏音频映射和未注册的 7z 方法仍明确拒绝，不将密码窗口等同于全部压缩／加密方法支持。
5. **其它原版表现。** 更多坏包窗口文案／时序，以及跨专辑目录的外置封面规则仍需单独对照；现有封面继续限定同一成员目录，防止串用别的专辑图片。

归档写回继续排除，不列入后续计划。
