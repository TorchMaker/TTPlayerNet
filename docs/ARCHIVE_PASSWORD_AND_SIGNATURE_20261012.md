# 压缩包密码、文件头识别与后缀提示

日期：2026-10-12。承接 [归档扩展与只读说明第 6 节](ARCHIVE_EXTENSIONS_AND_READONLY_20261012.md#6-仍有差异与后续顺序)。

本轮完成密码交互、密码记忆、文件头识别容错，并让外层压缩包复用「常规 → 选项 → 识别到错误后缀时提示更改」。压缩包成员继续只读；用户确认后的外层文件改名不修改压缩包内容。

## 1. 原版依据与新增能力的界线

参考 5.7.9 EXE SHA256：`c7999ea5823469c1684148cac1bd196009824348ccac5cdd45978f8fb574e28c`。

- `004738B5` 的归档工厂比较扩展名 `.zip`、`.rar`，分别创建对应对象，没有统一的文件头识别入口。
- `00474051` 保留成员顺序，生成 `archive|member` 身份。`004741A6` 先排除播放列表类型，再按注册音频类型导入；包内 CUE 仍通过内存 Reader 展开。
- ZIP 音乐读取 `0041F185` 要求 Deflate 结束标记；不能沿用皮肤 ZIP 的宽松读取规则。
- RAR 回调 `004DFF63` 的二进制只处理消息 1 的数据回传／取消，其余消息直接返回 0，没有填写密码的交互分支。不能把新版 UnRAR 有密码接口误认为原宿主已接通密码窗口。
- 原归档 IStream 虚表 `00522680` 的 Write／SetSize／Commit 实际返回 `E_NOTIMPL`。本轮继续拒绝成员写入，文件属性、封面及 CUE 不提供写回。

在独立原版进程内调用真实归档工厂和读取函数，Windows 11、XP、Win7 结果一致：传统加密 ZIP 和 AES ZIP 可以识别目录但读取失败；本次 RAR5 样本打开失败；7z、错误后缀和无后缀样本不被工厂接受。新增的密码交互、文件头容错和 7z 能力属于重建扩展，不宣称是原版原有行为。

## 2. 格式与密码支持

| 格式 | 本轮实现 |
| --- | --- |
| ZIP | 传统 ZipCrypto，以及 WinZip AE-1／AE-2、AES-128／192／256；Stored／Deflate 保持原有严格长度检查 |
| RAR | 沿用 UnRAR 7.3.1，接通密码参数；数据加密和文件名加密均进入同一交互流程 |
| 7z | 改由静态 LZMA SDK 26.04 解码；支持数据／文件名 AES 加密，以及 Copy、LZMA、LZMA2、PPMd、已注册的 BCJ／Delta 组合 |
| TAR、gzip、tar.gz、tgz | 本身没有标准密码层，继续正常只读解析；损坏、CRC 错误及未启用方法不会冒充密码输入需求 |

不依赖运行时的 7z.exe、WinRAR、UnRAR.dll 或额外加密 DLL。ZIP 使用 XP SP3 已有的 CryptoAPI，密码存储使用 DPAPI；没有增加 CNG 的静态依赖。

### 2.1 先验证，再交给解码器

ZipCrypto 的头部校验只有 8 位，不能据此认定密码正确。所有加密成员要完成解压、长度、CRC 或 AES 认证校验，才成功返回可播放流；验证失败不缓存为有效密码。RAR 也会在打开后继续报告密码错误，因此统一等待最终结果。

不加密的成员保持既有的后台渐进读取。加密成员完整校验时继续检查取消，等待超时按无输出进展计时；持续产生数据不会仅因超过固定 30 秒而失败。字典、元数据、成员数量和解压大小限制保留。

### 2.2 主线程与密码窗口

后台播放线程通过消息队列请求密码，界面线程显示 WTL 模态窗口。输入框掩码显示，默认不勾选记住密码；错误后可重试，也可取消。停止、换曲或关闭播放器会使请求失效并关闭窗口。

压缩包播放不再套用本地普通文件的同步 4 秒打开等待，否则界面线程会等解码器，解码器又在等界面输入密码。归档播放现在使用现有的异步打开完成／错误通知流程。取消不标记歌曲损坏，也不自动跳到下一首继续弹密码窗口。

导入时，只有加密目录或需要读取的加密 CUE 才要求密码；普通未加密目录可先列出曲目，在实际播放／读取成员时验证密码。

## 3. 记住密码的身份和保存

保存位置为播放器配置目录的 `ArchivePasswords.dat`。每条记录保存：

- 外层压缩包文件名，不保存原始完整路径。
- 整个压缩包的 MD5 与 SHA-256。
- 当前 Windows 用户 DPAPI 加密后的密码。

匹配规则是 **文件名相同，或者 MD5 和 SHA-256 同时相同**。任一身份条件符合，只代表可以尝试该密码，仍须进行真实解密验证；同名文件使用不同密码时会重试并提示。改名但内容相同的文件可按组合指纹找到密码。通过后缀提示改名时同步迁移会话身份及已记住的文件名。

密码不是明文 JSON，不出现在命令行或普通临时包中。独立文件信息助手接收与当前压缩包路径绑定的 DPAPI 数据包，最多携带 8 个候选；不会自动弹出无人处理的密码框。不能解密时保留「未读取」状态。

存储采用有界版本化记录、临时文件写入和原子替换，最多 256 条。保存失败会提示；仍可播放已验证的成员。哈希分块计算并检查取消；相同文件身份、大小和修改时间的指纹可在会话内复用，避免每个 CUE 分轨反复扫描整包。

DPAPI 数据仅适用于当前 Windows 用户；复制播放器到另一账户后，需要重新输入密码。这是保存方式的边界。

## 4. 文件头容错与后缀选项

### 4.1 识别顺序

强文件头签名优先于扩展名：ZIP、RAR4／RAR5、7z、gzip；TAR 必须通过完整首块校验和，不能只凭 `ustar` 字样。未识别出强签名时才按已有扩展名分派，让原有错误处理继续生效。

已覆盖错误后缀、没有后缀和压缩包格式互换后缀；即使把 ZIP 改成 `.cue` 或 `.m3u`，导入也先按真实归档处理。gzip 自动区分内部 TAR 与单文件流；缺少可用音频名称时，为其唯一虚拟成员补充可识别的音频后缀。

不扫描 EXE 内部查找 SFX，不根据几个模糊字符猜测格式；无后缀的全零空 TAR 没有足够头信息，不能可靠识别。

### 4.2 提示时机与选项

复用既有选项 `General/PromptExtensionCorrection`，默认值仍为启用：

| 操作／设置 | 行为 |
| --- | --- |
| 添加到列表、扫描歌曲信息 | 按文件头识别，不主动改名，也不触发后缀提示 |
| 成功打开并播放包内曲目，选项启用 | 检测外层压缩包后缀；不匹配时显示现有更改对话框 |
| 选项关闭 | 继续按文件头正常读取，不提示、不更改后缀 |
| 确认 | 将外层文件改为对应 `.zip`／`.rar`／`.7z`／`.tar`／`.gz`；gzip 接受已有 `.tar.gz`／`.tgz` 别名 |
| 目标重名 | 显示双方文件大小，由用户选择覆盖或加编号；编号冲突继续递增 |
| 取消 | 保持文件和播放不变 |
| 不再提示更改 | 关闭并保存同一个选项，不另设压缩包开关 |

只改外层文件名，ZIP／RAR／7z／TAR 成员名和 CUE 内容不变；播放列表、其他列表、媒体库、播放记录和歌词关联同步更新外层路径，保留各成员及分轨身份。覆盖目标包后，旧目标曲目的信息失效并待重新读取，不能把当前歌曲的信息复制给不同成员。

raw gzip 的虚拟成员名来自外层文件名。加编号后会重新取得该名字并更新逻辑路径，防止文件已经成功改名、继续播放却找不到成员。改名前释放活动读取者和归档缓存；完成后恢复播放位置及暂停状态。文件在确认期间变化时，原有身份检查会拒绝操作。

## 6. 构建与分发

LZMA SDK 固定 26.04，下载 SHA256：`bd98058d0e12c5da970dd4e5e1d8fa24f2d704914d96e69c28f92ed45421a439`。来源与 Public Domain 声明保存在 `ttpcomm/licenses/LZMA-SDK-PUBLIC-DOMAIN.txt`；源码构建时下载，许可证不嵌入 DLL。

旧 67 个导出、4 个扩展导出和 ABI 1／2 布局不变；密码与文件头能力掩码要求提高至 `2047`。Actions 下载校验与打包校验同步更新，仍默认使用最新版 ttpcomm。发布服务器前需先发布新核心 DLL，再构建播放器；本轮未向服务器发布。

`ttpcomm.dll` 为 690688 字节，较上一轮 632832 字节增加 57856 字节；仍是同一个兼容 XP／Win7 和新系统的 x86 DLL。核心与播放器静态导入审计通过。

本地输出：`rebuild/build/Release/TTPlayerRebuild-2026.10.12.zip`，核心单独包为 `ttpcomm/build/Release/ttpcomm-2026.10.12.zip`。包内 SHA256 清单及私有 `release-verification.json` 记录最终文件，不包含测试、样本或密码数据库。
